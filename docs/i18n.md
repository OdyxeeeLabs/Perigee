# Internationalisation (i18n)

The web app uses `next-intl`. English (`web/messages/en.json`) is the canonical
message catalogue; `web/lib/locale/locales.ts` defines the eight shipped
locales, their endonyms, BCP 47 tags and direction. A locale catalogue that is
missing a key falls back to English, so a gap is easy to miss in a locale that
is rarely exercised.

## Adding a new message

1. Add the key and the English string to `web/messages/en.json`. Use a flat
   dotted key (`feature.section.action`) and keep placeholders named
   (`{count}`, `{name}`).
2. Use the key in the component:
   - Pages Router / client component: `const t = useTranslations(); ... t("feature.section.action")`.
   - App Router server component: `const t = await getTranslations(); ... t("feature.section.action")`.
3. Add a translation to any locale catalogue where a translation exists. A
   catalogue may stay partial — the untranslated key falls back to English.
   Never paste a raw English sentence into a non-English catalogue just to
   silence the check; the wording is allowed to differ and is never compared.
4. Run `cd web && node scripts/i18n/check-messages.cjs` (or `yarn i18n:check`),
   then `node scripts/i18n/check-manager-copy.cjs` for manager routes.

## Completeness check

`web/scripts/i18n/check-messages.cjs` compares the key sets of every
`web/messages/*.json` file. It fails on:

- **missing** — a key in `REQUIRED_KEYS` is absent from a catalogue. This is a
  deliberately small set of core UI strings shared by every shipped locale;
  add to it only when a message truly must be translated everywhere.
- **unexpected** — a catalogue defines a key that does not exist in `en.json`
  (usually a typo that no component can ever reach).

It does **not** compare values, so two locales may translate the same key
differently, and it never rewrites a catalogue. The output lists, per locale,
how many of the English keys are translated.

CI runs the check in `.github/workflows/i18n-messages.yml`; deleting a required
key from any locale fails the build. The same rules are unit tested in
`web/lib/locale/messages.test.cjs`.

## Manager route copy

`web/scripts/i18n/check-manager-copy.cjs` scans the manager and onboarding
routes for JSX text literals and for `t("...")` keys that do not exist in
`en.json`. Developer diagnostics (comments, TODOs, code identifiers) are not
user-visible and are ignored. Its tests live in
`web/lib/i18n/manager-copy.test.cjs`.

## Locale-aware rendering

`web/lib/locale/format.ts` centralises numbers, compact numbers, percentages,
currency, dates, times and relative times. Use it instead of `toLocaleString()`
or `toFixed()` in views. When a visual value is rounded, expose the unrounded
value to assistive technology through `<FormattedAmount />` from
`web/components/ui/FormattedAmount.tsx`. Protocol values must stay unrounded
in calculations and transaction submission; round only at render time.

RTL is driven by the document `dir` attribute (`web/components/LocaleSync.tsx`).
Prefer Tailwind logical utilities (`text-start`/`text-end`, `ms-*`, `ps-*`),
and mirror only icons whose meaning is directional via `data-mirror-rtl`.
`data-no-mirror-rtl` opts a control out. RTL workflow screenshots are in
`web/e2e/visual/visual.spec.ts`.
